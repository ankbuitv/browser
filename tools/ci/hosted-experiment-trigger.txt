HOSTED_CONSTRAINED_EXPERIMENT - one-shot trigger (temporary)
============================================================

Starts the controlled run of
.github/workflows/chromium-hosted-constrained-experiment.yml, because the
automation credential cannot create workflow_dispatch events:

    HTTP 403: Resource not accessible by integration
    POST /repos/ankbuitv/browser/actions/workflows/{id}/dispatches

Removed again once the run has FINISHED - not while it is in flight, because
editing the workflow's trigger set cancels the run that is flying.

Run 9
-----
Runs 1-4: bugs in this repository's own workflow code.
Run 5: sync finished, toolchain hook died with the budget already spent.
Run 6: the packaged Chromium toolchain lives in a Google Cloud bucket that
  refuses anonymous callers, so DEPOT_TOOLS_WIN_TOOLCHAIN=0 is forced.
Run 7: sync 15 min, hooks green, verify-patches failed in 7 s.
Run 8: same. The missing piece was that build.mjs writes only the command
  it ran into its stage log and streams the tool's real output to the
  console - which is the one thing this environment cannot read. So the
  run could name the stage but never the check.

This run tees that console output into artifacts/logs/*.console.log and
publishes it on failure, so verify-patches finally says which check fails.
It also reads the Visual Studio installer's dd_setup_*.log instead of its
update-check log, and falls back to winget for the pinned SDK.
